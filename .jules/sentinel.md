## 2025-03-15 - Hardcoded JWT Secret Key in internal/auth
**Vulnerability:** A hardcoded, easily guessable secret key (`"your_secret_key"`) was being used for signing and validating JSON Web Tokens (JWT) in `internal/auth/auth.go`. This is a critical security risk as it allows anyone with access to the codebase (or an attacker who guesses the weak key) to forge valid tokens and bypass authentication entirely.
**Learning:** Hardcoded secrets in source code are a persistent vulnerability pattern. They indicate a failure to properly separate configuration from code and often leak into version control systems. In Go 1.16, unit tests involving environment variables need careful management with `os.Setenv` and `defer os.Setenv` (to restore state) because `t.Setenv` was introduced in 1.17.
**Prevention:** Never hardcode secrets. Always load sensitive configuration (like JWT secrets, database passwords, API keys) from environment variables or a secure secret management service. Use a secure, randomly generated string of sufficient length (e.g., 256 bits for HS256) for the JWT secret in production. Ensure tests that temporarily modify environment variables properly restore the previous state to prevent test interference.
